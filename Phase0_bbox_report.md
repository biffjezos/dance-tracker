# Implementation Report: Phase 0 — Bounding-box awareness foundation

**Branch:** `claude/bbox-phase-0` (pushed, PR not yet opened — awaiting evaluator per the phased cycle)
**Commit:** `bcf895d`
**Spec:** Bounding-box awareness spec, Phase 0 — per `BBOX_CONVENTIONS.md`

## Summary

Lands the zero-behavior-change foundation for bbox-awareness: a `Rect`
type, a defaulted `Operation::output_bbox` trait method, a new
`Context.input_bboxes` field, and both executors threading `(Value,
Rect)` pairs through their private recursion instead of bare `Value`.
Every operation in the tree inherits the full-frame default with no
edits of its own, and no operation's pixel output changes.

## What was implemented

- **`engine/src/compositor/bbox.rs`** (new file): `Rect { x0, y0, x1,
  y1 }` — signed (`i32`) half-open pixel-index bounds `[x0,x1) x
  [y0,y1)`, so intermediate math (a negative `grow`, an off-canvas
  `MOVE` offset) can be computed directly and clamped afterward rather
  than needing saturating arithmetic at every step.
  - `full(width, height)` — the entire frame, today's implicit behavior.
  - `empty()` — canonical zero-sized rect at the origin; `is_empty()`
    checks `x1 <= x0 || y1 <= y0`, covering both `empty()` itself and any
    rect degenerated by an intersection with nothing left in common.
  - `intersect` — shared region of two rects, `empty()` if disjoint or
    if either operand already is.
  - `union` — smallest rect containing both; an empty operand is
    **ignored** (returns the other operand unchanged), not treated as
    "extend to include the origin" — the specific edge case
    `BBOX_CONVENTIONS.md` calls out.
  - `grow(amount)` — expands every side by `amount` (negative shrinks);
    an empty rect stays empty. Does **not** clamp to the frame itself —
    callers (e.g. Phase 2's `BLUR`) intersect the result against
    `Rect::full` themselves.

- **`engine/src/compositor/input.rs`**: `find_bbox(bboxes: &[(Input,
  Rect)], key: Input) -> Option<Rect>`, same shape as the existing
  `find_input`.

- **`engine/src/compositor/operations.rs`**: `Operation::output_bbox`,
  a new defaulted trait method (same pattern as `is_live()`):
  ```rust
  fn output_bbox(&self, ctx: &Context, _input_bboxes: &[(Input, Rect)], _output: &Value) -> Rect {
      Rect::full(ctx.meta.width, ctx.meta.height)
  }
  ```
  `output` is unused this round — kept in the signature so a future
  content-derived box (out of scope, tracked in `PARKED_WORK.md`) never
  needs a second trait-signature change.

- **`engine/src/compositor/context.rs`**: `Context` gains `pub
  input_bboxes: Vec<(Input, Rect)>`. `Context` already
  `#[derive(Default)]`s, so no other construction site anywhere in the
  codebase needed to change.

- **`engine/src/compositor/executors/render.rs`**: `RenderExecutor::evaluate`
  and `evaluate_profiled` now return `(Value, Rect)` instead of bare
  `Value`, and `memo`/`CachedNode` carry the bbox alongside the value.
  Immediately before calling `execute()`, a per-node `Context` is built
  (`Context { input_bboxes: input_bboxes.clone(), ..ctx.clone() }`), then
  `output_bbox(&node_ctx, &input_bboxes, &value)` computes this node's own
  box afterward. The public `Execute::execute()` still returns bare
  `Vec<Value>` — the `Rect` threading is entirely private to the
  recursion.

- **`engine/src/compositor/executors/preview.rs`**: identical threading
  applied to `evaluate_unmemoized` and `evaluate_memoized`.

- **No operation file changed.** No `execute()` body changed anywhere.
  No change to the public `Execute` trait.

## Acceptance criteria checklist

1. ✅ `cargo build`/`cargo test` pass; **zero test modifications outside
   `compositor/`** — confirmed via `git status --short`, diff is
   entirely within `compositor/` (`bbox.rs` new, `context.rs`,
   `executors/preview.rs`, `executors/render.rs`, `input.rs`, `mod.rs`,
   `operations.rs`).
2. ✅ An arbitrary operation's default, unoverridden `output_bbox()`
   returns exactly `Rect::full(ctx.meta.width, ctx.meta.height)`.
3. ✅ `Rect::intersect`/`union`/`grow` unit tests, including the
   empty-operand `union` edge case.
4. ✅ Render integration test confirms byte-identical output for an
   existing multi-node graph (`chromakey → add`) versus hand-derived
   expected pixels — proves the new threading changed nothing
   observable.

## Out of scope (per spec, untouched this phase)

- Any operation overriding `output_bbox()` to something tighter than
  full-frame (Phase 1: `RESIZE`/`MOVE`).
- Any operation consuming `ctx.input_bboxes` to skip real work (Phase 3).
- `BLUR`'s box-growing (Phase 2).
- Content-derived boxes (chromakey/hue_key) — explicitly excluded from
  this round per `PARKED_WORK.md`.
