Implement the following compositor architecture improvements. Keep the existing Operations → Nodes → Graph → Executors design. Do not redesign the architecture.

==================================================
1. Dynamic Output Resolution
==================================================

Move render resolution ownership from App into the compositor graph.

Current problem:
Changing the HTML canvas size only changes the display surface. The internal graph still renders using the old resolution.

Implement:

- Add width and height to Graph state.
- Add a Graph method:

    set_resolution(width, height)

- Pass the graph resolution through Context so operations can access it during execution.
- Rendering should use the graph resolution, not the HTML canvas size.

Requirements:

- Canvas dimensions remain only the presentation size.
- Internal Frames, Masks, Images and generated effects must use the graph resolution.
- Changing resolution should not require rebuilding the graph.

==================================================
2. Remove Fixed Dimensions From Operations
==================================================

Operations should not permanently store render dimensions.

Current examples:

- Rings::new(width, height, ...)
- Text::new(width, height, ...)
- Video source storing target_width/target_height

Change:

- Remove width/height constructor parameters where they represent render output size.
- Operations should read current dimensions from Context during execution.

Example:

Before:

    Rings::new(width, height, settings...)

After:

    Rings::new(settings...)

During execute:

    ctx.width
    ctx.height

The operation must automatically adapt when graph resolution changes.

==================================================
3. Graph Validation Cache
==================================================

Keep the current validation algorithm, but avoid validating every render tick.

Add validation state to Graph:

    Dirty
    Valid
    Invalid(OperationError)

Rules:

- add_node() marks graph dirty.
- Any future structural graph modification marks graph dirty.
- Before execution, validate only when state is Dirty.
- Store the validation result.

Do not remove the existing cycle detection logic.

==================================================
4. Generic Operation Mutation API
==================================================

The project already supports operation mutation through:

    as_any_mut()

and examples like:

    set_text_content()

Add a reusable Graph helper:

    operation_mut<T>(node_id) -> Option<&mut T>

Purpose:

Allow changing operation parameters without rebuilding the graph.

Example:

Instead of:

    destroy graph
    recreate Rings with new size

Use:

    graph.operation_mut::<Rings>(node_id)
          .set_size(value)

Use this pattern for future live parameter changes:
- effect settings
- generators
- masks
- blend parameters

Keep the existing operation mutation mechanism. 
Do not introduce Any/downcasting for Value handling.
Value must remain enum-based.

The existing Operation::as_any_mut() mechanism may remain for live parameter editing until a dedicated parameter system exists.
